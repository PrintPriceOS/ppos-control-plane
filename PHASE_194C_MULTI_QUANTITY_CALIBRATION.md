# Phase 194C — Multi-Quantity Calibration Architecture & Design Specification

## Overview

Phase 194C extends the PrintPrice OS Control Plane pricing calibration engine from fitting a single quantity target ($q, T$) to fitting **multiple quantity and price targets simultaneously** for a single canonical `BookSpec`.

Existing single-point calibration fits parameter adjustments against a single volume observation, which frequently causes overfitting at that specific volume while skewing rates at higher or lower volumes. Phase 194C fits a coherent multi-point manufacturing price curve:

$$T = \{ (q_1, M_1), (q_2, M_2), \dots, (q_N, M_N) \}$$

without mutating active rates (`printer_nodes.rates_json`), without automatically activating quantity economics, and without bypassing governed acceptance.

---

## 1. Multi-Target Session & Calibration Contract

### 1.1 Target Schema & Contract
A multi-quantity calibration session accepts a set of target points:

```json
{
  "calibrationMode": "MULTI_QUANTITY",
  "calibrationTargets": [
    {
      "quantity": 500,
      "targetManufacturingPrice": 4321.00,
      "currency": "EUR",
      "targetBasis": "MANUFACTURING_PRICE",
      "eligibilityStatus": "ELIGIBLE",
      "sourceEvidenceId": "evd_natur_001",
      "sourceOfferIndex": 0
    },
    {
      "quantity": 600,
      "targetManufacturingPrice": 4604.00,
      "currency": "EUR",
      "targetBasis": "MANUFACTURING_PRICE",
      "eligibilityStatus": "ELIGIBLE",
      "sourceEvidenceId": "evd_natur_002",
      "sourceOfferIndex": 1
    },
    {
      "quantity": 700,
      "targetManufacturingPrice": 4846.00,
      "currency": "EUR",
      "targetBasis": "MANUFACTURING_PRICE",
      "eligibilityStatus": "ELIGIBLE",
      "sourceEvidenceId": "evd_natur_003",
      "sourceOfferIndex": 2
    }
  ]
}
```

### 1.2 Target Basis & Transport Exclusion
- **Basis Restriction:** `targetBasis` MUST be `MANUFACTURING_PRICE`.
- **Logistics Exclusion:** Transport/logistics costs (e.g. Natur €325 transport charge) must **never** enter manufacturing calibration. Input payloads specifying `DELIVERED_TOTAL` or mixed bases are rejected immediately (`INVALID_TARGET_BASIS`).

## 2. Evidence Eligibility & Selection

Calibration targets must be derived from explicitly eligible evidence points:
- **`ELIGIBLE`**: Quotation passes arithmetic verification (Phase 194A) and explicit evidence review. Used in solver optimization.
- **`REQUIRES_REVIEW`**: Point has minor discrepancy or unverified fields. Excluded from solver unless confirmed.
- **`REJECTED`**: Arithmetic failure or inconsistent source quotation (e.g. Stutensee unit price contradiction). Strictly excluded.

---

## 3. Objective Function & Residual Metrics

### 3.1 Objective Function
The inverse pricing solver minimizes the normalized sum of squared manufacturing price residuals across all $N$ targets:

$$r_i = \frac{\hat{M}(q_i) - M_i}{\max(M_i, \epsilon)}$$

$$S(\theta) = \sum_{i=1}^N w_i \cdot r_i^2$$

where:
- $\hat{M}(q_i)$ is the forward price generated by `@ppos/pricing-engine` at quantity $q_i$ using candidate rates $\theta$.
- $M_i$ is the target manufacturing price at quantity $q_i$.
- $w_i$ defaults to $1.0$.
- $\epsilon = 10^{-6}$ prevents division by zero.

### 3.2 Per-Point & Aggregate Residuals
To prevent hiding trade-offs across quantities, calibration runs return granular per-point metrics alongside aggregate curve statistics:

- **Per-Point Metrics:**
  - `quantity`: $q_i$
  - `targetManufacturingPrice`: $M_i$
  - `predictedManufacturingPrice`: $\hat{M}(q_i)$
  - `absoluteResidual`: $\hat{M}(q_i) - M_i$
  - `percentageResidual`: $\frac{\hat{M}(q_i) - M_i}{M_i} \times 100\%$
  - `withinTolerance`: Boolean status against governance thresholds

- **Aggregate Curve Metrics:**
  - `pointCount`: Total number of evaluated target points
  - `meanAbsoluteResidual`: Average absolute deviation across targets
  - `maxAbsoluteResidual`: Maximum absolute deviation across targets
  - `meanPercentageResidual`: Average percentage deviation across targets
  - `maxPercentageResidual`: Maximum percentage deviation across targets
  - `objectiveValue`: Final scalar value of objective function $S(\theta)$

## 4. Identifiability Governance

A multi-point solver must diagnose whether a given set of targets can uniquely identify candidate rate adjustments.

### 4.1 Diagnostic Metadata
Each calibration run computes:
- `targetPointCount`: $N$ (number of eligible target observations)
- `freeParameterCount`: $P$ (number of unconstrained/adjustable parameters)
- `degreesOfFreedom`: $DF = N - P$

### 4.2 Identifiability Statuses
- **`EXACTLY_DETERMINED`** ($N = P > 0$): Exact system fit expected.
- **`OVERDETERMINED`** ($N > P > 0$): Optimization fits best-fit approximation curve across excess targets.
- **`UNDERDETERMINED`** ($0 < N < P$): System is underconstrained. Infinite parameter sets exist to fit the targets. Solver flags run status as `UNDERDETERMINED` candidate. Candidate cannot proceed to governed acceptance without explicit parameter locking or regularization.
- **`UNIDENTIFIED`** ($N = 0$ or $P = 0$): Insufficient data or zero free variables.

## 5. Canonical Engine Composition & No-Double-Count Rule

### 5.1 Pricing Engine Composition
The canonical pricing engine (`@ppos/pricing-engine`) natively accounts for quantity-dependent costs:
- Setup cost amortization per press run
- Paper sheet and kilo calculations per volume
- Binding setup vs run-rate steps

Phase 194C evaluates candidate pricing states directly through `buildPriceCalibrationAdapter.js` by calling `buildPrice(...)` at each target quantity $q_i$.

### 5.2 No-Double-Count Rule
Phase 194B Quantity Economics provides piecewise marginal pricing abstractions. When evaluating manufacturing price targets, Phase 194C evaluates the candidate canonical rate vector $\theta$. Phase 194B quantity economics adjustments must act as an explicit governed adjustment layer or rate scalar, rather than adding an independent secondary manufacturing cost model on top of press/paper calculations.

## 6. Fixtures & Validation Results

### 6.1 Natur Canonical Fixture
- **Specification:** Natur 135g / 170g Hardcover BookSpec
- **Targets:**
  - $q=500 \rightarrow M=4321$ (Delivered: €4646 - €325 transport)
  - $q=600 \rightarrow M=4604$ (Delivered: €4929 - €325 transport)
  - $q=700 \rightarrow M=4846$ (Delivered: €5171 - €325 transport)
- **Evaluation:** Evaluated simultaneously in solver. Transport charge (€325) strictly excluded from calibration objective.

### 6.2 Synthetic Exact Linear Fixture
- **True Model:** Fixed = €1000, Marginal = €2.50/copy
- **Targets:** $(100, 1250), (200, 1500), (300, 1750)$
- **Solver Result:** Recovers exact solution parameters ($R^2 = 1.0$, objective = 0.0) within numerical tolerance $\le 10^{-6}$.

---

## 7. Candidate Results vs Governed Acceptance

Phase 194C outputs an **unaccepted calibration candidate** (`mode: "MULTI_QUANTITY"`):
- `printer_nodes.rates_json` remains untouched.
- `quantityEconomics` remains inactive.
- Session/Run persistence records candidate results with `is_accepted = false`.

Governed acceptance, revision creation, supersession, and activation are deferred entirely to Phase 194D.

## 9. Phase 194D Handoff

Phase 194D will build upon Phase 194C by introducing:
1. **Multi-Quantity Curve Tolerance Policies:** Governing aggregate metrics (`maxPercentageResidual`, `meanPercentageResidual`) for acceptable multi-point curves.
2. **Governed Curve Acceptance:** Creating immutable revision snapshots for multi-quantity calibrated models.
3. **Controlled Activation:** Safe promotion of multi-quantity calibration candidates to active tenant pricing models under Controlled Beta constraints.
