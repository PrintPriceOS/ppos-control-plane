# Phase 191G.1: Secret Key Management & Audit Redaction Review

## 1. Key Derivation & Fail-Closed Safety
- **AES-256-GCM Key**: Sourced from `process.env.ENCRYPTION_SECRET`. In production, startup fails if `ENCRYPTION_SECRET` is unconfigured.
- **Nonce/IV**: Generated per-encryption call via `crypto.randomBytes(12)`.
- **Auth Tag**: Mandatory `authTag` verification attached to ciphertext string (`ivHex:authTagHex:encryptedHex`).

## 2. Lookup Hash Purpose
```text
SECRET_LOOKUP_HASH_PURPOSE: IDENTIFIER_LOOKUP_AND_AUTHENTICATION_VERIFICATION
```
- Plaintext API bearer secrets (`phsec_...`) are hashed using SHA-256 (`key_hash`). Authenticated requests lookup by `key_id` and compare `key_hash` without decrypting ciphertext.

## 3. Secret Redaction Audit
- Audits generated by `printhouseIntegrationCredentialService.js` and `printhouseWebhookService.js` redact all raw secrets (`rawSecretExposed: 'ONCE_UPON_CREATION_REDACTED_FROM_LOGS'`, `maskedSecret: '••••••••••••••••'`).
- Plaintext secrets never appear in logs or secondary queries.
